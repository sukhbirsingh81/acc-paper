## Assessment

The paper has a coherent contribution as an implementation and measurement study: it connects graph routing, flight-phase waypoint construction, trajectory generation and conflict checking, and shows where time is spent. Its strongest result is the distinction between fast graph search, more expensive trajectory generation, and the much larger complete conflict-checking call in the evaluated deployment.

My reviewer recommendation for the incoming draft would be **major revision**, primarily because several claims exceeded the recorded measurements or scripted assertions. The revisions below address those claims without changing experimental observations. The remaining evidence gaps should be considered before submission; clearer prose cannot establish operational safety, resolution completeness, or comparative algorithm performance.

## Remaining issues before submission

1. **Reproducibility package and exact evaluated software.** The manifest still records a detector commit “+ closest-approach fix (uncommitted).” Branch heads alone do not pin that evaluated state. Archive the exact evaluated source/patch and permitted aircraft configuration, input data and analysis scripts. The manuscript gives generic aircraft assumptions but not a complete, independently reconstructible performance configuration. Do not guess these values from current development code.
2. **Experimental strength.** There is one fixed traffic sequence and schedule seed, no comparison against another resolution method, and no monolith/service ablation. The revised paper consistently presents a bounded prototype study. Broader efficiency or resolution-performance claims would need additional experiments. A detector component-level timing study is needed to attribute its latency to fetching, indexing or queries.
3. **Scenario assertions.** If stronger validation is desired, assert successful statuses for resolvable cases, check the crossing location explicitly, and require a successful HTTP response for the non-resolution case. The existing fifth assertion also permits an HTTP failure to count as passing, although the archived observed response is HTTP 200. Replace the duplicate with an additional scenario before claiming five distinct encounter setups. These are future code/test improvements; this review corrected the manuscript to match the existing evidence.
4. **Author information and declarations.** Confirm affiliation addresses, funding, software/version identifiers, disclosure/data-sharing permissions and the companion manuscript's publication status. Existing open questions remain in `AUTHOR_QUERIES.md`; they are not resolved by this review.
5. **Literature comparison.** The corrected table is qualitative, not a performance comparison. Check remaining entries against complete source papers before making a stronger novelty claim, particularly the unpublished companion paper.
